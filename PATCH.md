# T3 Code compatibility patches

## Purpose

Keep desktop usable on the user's Intel Mac running unsupported macOS 15. User reports that a newer Chromium graphics change causes CPU rendering and lag, and has downgraded Electron locally. The graphics cause and runtime improvement have not been independently verified during this documentation setup.

Keep project Codespaces work available with the user's existing local provider login. Remote execution must not depend on maintainer-owned relay infrastructure.

- Preserve original staged, unstaged, and untracked work. Carry the pending compatibility changes below and this specification into the review result.

## P001: Preserve the compatible Electron runtime

- Status: active. Version observed in the user's existing patch, runtime result not independently verified.
- Required behavior: preserve desktop usability on the target Intel Mac. Retain exact Electron `43.6.0` until another version is verified on that machine and the constraint is deliberately revised.
- Implementation hints: `apps/desktop/package.json` pins Electron to `43.6.0` instead of upstream's `44.4.5`; `pnpm-workspace.yaml` aligns the minimum-release-age exception; `pnpm-lock.yaml` resolves the desktop importer and affected peer snapshots to `43.6.0`.
- Regenerate the lockfile through the current package manager when dependencies change. The current lockfile still contains `44.1.0` entries, so checking for that string globally is not a valid test of the active desktop runtime.
- Verification: confirm the desktop manifest, resolved importer, installed Electron binary, and packaged runtime agree. On the target machine, inspect Electron GPU feature status and renderer information, then check representative scrolling, chat rendering, and CPU use against the user's working baseline. Do not claim acceleration based only on compilation or a version number.
- Retirement: a newer runtime satisfies these hardware checks, or the user changes the hardware requirement. If upstream requires incompatible APIs, adapt those call sites or report the concrete blocker; do not silently upgrade Electron.

- Status: active, observed alongside the runtime downgrade.

Retain project Settings, command palette, and keyboard access. A bound target remains manageable while workspace switching is locked; status and accessibility labels must reflect unavailability.
- Preserve durable project bindings and operation idempotency. Identical request retries return the saved operation after account and input validation, without repeating eligibility or idle checks for new work. Disconnected bound targets fail instead of executing locally. Failed reconnects clear old executor registrations, forwards and connected status before remote process replacement. Resolve provider guards from the thread's project binding, including existing worktree threads outside its root. Lifecycle changes refuse active or waiting turns and reserve every affected project and shared target until completion; provider starts and binding changes respect those reservations. Deletion removes bindings and remote compute while keeping local history. Agent management requires explicit opt-in and full-access callers. Lifecycle controls honor the destination environment's access-write grant. Standard paired task clients read project bindings and observe changes without that grant, so bound drafts use the main checkout on every client. Web, desktop and mobile sends and mobile queue creation wait for confirmed binding status on Codespaces-capable hosts. Unloaded configuration waits; a loaded older host that omits the Codespaces flag keeps local sending without a binding query. Failed binding reads block sending and offer retry without losing drafts or substituting a local workspace. Run on status follows lifecycle completion and binding changes across devices, even after its panel closes, without duplicate inventory reads on the initial snapshot. Older hosts retain preview navigation without workspace URL resolution. Desktop previews of remote-host loopback URLs run in that host's browser. Concurrent preview requests wait for the same ready SSH forward. Remote content search uses the same native search service as local work, including regex syntax, case rules, whole-word edges, Unicode highlight ranges and invalid-regex fallback feedback. Bootstrap caches the host-pinned search engine in private executor storage; index creation stays lazy. Workspace image, HTML and PDF previews read remote files and sibling assets through signed URLs; signed URLs retain their original local or Codespace location, and unavailable bindings never substitute local files. Remote preview directory and linked-asset paths use POSIX separators even on Windows hosts. Safe links within the remote workspace remain previewable. Attached files stream to the executor before turns or steering, and provider prompts reference their remote paths without adding them to Git checkpoints. Steering uses the active turn's workspace even when provider sessions span projects. Remote attachment paths survive reconnects, reuse identical uploads, and retain a bounded cache without evicting files still referenced by history.
- Implementation boundary: a bundled workspace worker and pinned Codex exec-server run remotely. Normal server development startup builds the worker before launching. Local Codex 0.160.1 or later registers the private executor using native environment APIs. Other providers and additional worktrees are explicitly unsupported initially. Queued mobile creations refresh the binding at delivery, after attachment preparation. Bound projects ignore the saved worktree, branch and origin setup; failed binding reads keep tasks queued for retry. Web, desktop and mobile unstarted drafts use the main checkout while bound, overriding saved worktree choices and worktree defaults; unsupported workspace controls are disabled. Web multi-model sends are refused while bound because they require separate worktrees. Workspace routing recognizes POSIX and Windows root aliases and child paths, rejects sibling directories, converts Windows child paths to POSIX remote paths, and translates structured results back to host paths. Disconnected Windows children never run locally. Absolute host-file links outside the bound workspace still read the host file; relative and absolute workspace paths read the executor and fail when disconnected. Routing preserves commit text and file contents. Remote directory listings retain Git ignore marks. Remote file search supports shortened fuzzy queries, exact filename ranking, filters and truncation. File saves accept the same contents as local saves, without a lower JSON request limit or escaping overhead; streamed writes preserve existing permissions and safe file symlinks. Preview snapshots and recent URLs preserve the application URL across changing SSH ports; URL resolution honors the destination preview-operate grant. Credential files are never copied remotely. SSH forwards belong to the controller connection and close with it.
